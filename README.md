# Hams_Alarm

An Android alarm clock that can ring at a **time**, when you **arrive somewhere**, or only when **both** are true.

- **Alarms**: three trigger modes per alarm.
  - **Time**: a normal alarm with repeat days.
  - **Location**: drop a pin and set a 100 m – 2 km radius. Rings when you enter the area.
  - **Time + Location**: rings only once it's time *and* you're there, with an optional time window.
- **Clock**: the current time, plus saved world cities.
- **Timer**: a countdown with 1 / 5 / 10 / 25 min presets. It keeps running in the background and rings with the alarm sound.
- **Stopwatch**: laps, with the best and worst lap highlighted.

Built with Expo SDK 58, React Native 0.88, TypeScript, expo-router, Zustand, react-native-webview (MapLibre + OpenFreeMap), expo-location, expo-task-manager and expo-notifications. Icons are from lucide-react-native. The alarm sound is generated by `scripts/generate-alarm-sound.js`.

## Install the app (share it with anyone)

The latest Android build is an **APK** that installs on any Android phone without the Play Store:

1. Open the build's download link on the phone (or send the `.apk` file over WhatsApp, Drive or email).
2. Tap it, then allow "Install unknown apps" for that browser or messaging app when Android asks.
3. Open **Hams_Alarm** and go through the welcome screen to grant permissions.

Build a fresh APK at any time:

```bash
EAS_NO_VCS=1 npx eas-cli@latest build -p android --profile preview
```

The project is linked to the Expo account **@serenityeye** (`hams-alarm`). The signing keystore is stored on Expo's servers, so every new APK installs over the previous one.

## Design

"Coloured paper", adapted from the Pastor Ed slide system:

- **Flat colour per screen, never all-black.** Alarms, edit and settings are cream, Clock is teal, Timer is ruby, Stopwatch is plum, and the Ring screen is gold. A light film grain sits over everything (`assets/art/grain.png`).
- **League Spartan only**, in heavy weights. Times use `components/Digits.tsx`, which puts every digit in a fixed-width cell. League Spartan has no tabular figures, so without this, ticking numbers would jitter.
- **Flat SVG illustrations with transparent backgrounds** (`assets/illustrations/*.svg`): clock, pin, clock + pin, hero, globe, ringing clock, hourglass and stopwatch. Each was drawn in Gemini as flat art in the app palette, then traced with `scripts/vectorize.py`. That script snaps colours to the palette, makes the background transparent and runs vtracer. `node scripts/build-illustrations.js` bundles them into `lib/illustrations.ts`, and they render with `<Illustration name="clock" />` or `<IllustrationDisc />`. Prompts are in `design/prompts/v_*.txt` and the source drawings in `design/raw/v_*.jpg`. The app icon is still the Gemini brass-clock photo.
- The theme lives in `lib/theme.ts`. Each screen picks one with `<Screen theme="teal">`, and components read it through `useTheme()`.

### Maps: free, no API key

Maps use **MapLibre GL JS** inside a WebView with **OpenFreeMap** vector tiles (https://openfreemap.org). Both are free, need no sign-up or key, and have no usage limits. ## Build a dev APK with EAS

This app uses native modules that Expo Go doesn't include (background geofencing, maps, custom notification sound). It needs a **development build**.

```bash
npx eas-cli@latest login
npx eas-cli@latest init          # first time only: links the project to your Expo account
npx eas-cli@latest build -p android --profile development
```

If you have EAS CLI installed globally (`npm i -g eas-cli`), the same command is `eas build -p android --profile development`.

When the build finishes, open the link on your phone and install the APK. Then start the dev server on your computer:

```bash
npm start
```

Open the Hams_Alarm app on the phone and connect to the server. Scan the QR code, or use the same Wi-Fi and pick the server from the list. JS changes hot-reload. **Native changes need a new build.** That means `app.config.ts`, plugins, permissions or the sound file.

## Testing without walking anywhere

In a dev build, open any saved alarm. The **DEV · Test trigger** panel at the bottom has three buttons:

- **Simulate arrival**: runs the real geofence-enter code path (`handleTransition`).
- **Leave**: the geofence-exit path. For Time + Location, this cancels an early-arrival ring.
- **Ring now**: starts a ring session straight away.

The panel only renders when `__DEV__` is true, so it never ships in `preview` or `production` builds.

Suggested on-device checks:

1. **Time alarm, app killed**: set an alarm 2 minutes ahead, swipe Hams_Alarm away, lock the phone. It should ring, and Stop / Snooze in the notification should work.
2. **Location alarm**: create one around your current block, then press *Simulate arrival*. Then try a real one on a walk or ride.
3. **Time + Location, early arrival**: set the time 3 minutes ahead and press *Simulate arrival* now. It should ring at the set time. Press *Leave* before then to check that the ring is cancelled.
4. **Time + Location, time first**: set the time 1 minute ahead and wait for it to pass. Nothing should ring. Press *Simulate arrival* and it should ring immediately.
5. **Timer**: start a 1-minute timer, leave the app, and confirm it rings.
6. **Reboot**: enable a location alarm and reboot the phone. Location alarms resume when the app is opened, or within about 15 minutes via the background task (see limitations).

Unit tests cover the scheduling logic: time maths, the Time + Location state machine, the notification plan and time zones.

```bash
npm test
npm run typecheck
```

## How it works

```
app/                  expo-router screens
  (tabs)/             clock · index (alarms) · timer · stopwatch
  alarm/[id].tsx      create / edit (id = "new" for a new alarm)
  ring.tsx            full-screen ringing UI
  permissions.tsx     explained permission steps
  cities.tsx          world-clock city picker
components/           UI: AlarmCard, MapPicker, Toggle, SegmentedControl…
lib/
  types.ts            Alarm model
  time.ts             occurrences, windows, Time + Location state machine (pure)
  ringPlan.ts         which notifications should exist right now (pure)
  notifications.ts    channels, actions, applying the plan to expo-notifications
  engine.ts           syncAll(), geofence transitions, ring / stop / snooze
  tasks.ts            TaskManager tasks (geofence, keep-alive, notification actions, re-sync)
  storage.ts          AsyncStorage (shared by the UI and headless tasks)
store/                Zustand stores (alarms, timer, stopwatch, cities)
hooks/                useNow, useLivePosition, useHealth
scripts/              generate-alarm-sound.js
design/               Gemini prompts (design/prompts) and original images (design/raw)
```

**One idempotent sync.** `syncAll()` rebuilds everything from storage: scheduled notifications, geofences, the keep-alive service and the periodic task. It runs on launch, on returning to the foreground, after every edit, in every background task, and every ~15 minutes via `expo-background-task`. This is how geofences come back after a reboot, and how anything missed while the app was killed gets caught up.

**Ringing.** `expo-notifications` can't loop a sound or launch a full-screen intent. So a ring is a short **chain** of notifications: one at the ring time, then a follow-up every 30 s for 5 minutes. Each one plays the ~28 s alarm tone on a channel that:

- uses Android's **alarm audio stream**, so it follows alarm volume and still sounds in silent mode;
- is set to max importance;
- bypasses Do Not Disturb when allowed.

Triggers use `delivery: 'alarmClock'` (`setAlarmClock`), so they fire on time while the phone is idle. Stop / Snooze in the notification work even when the app is killed, through a background notification task. When the app is open, the ring screen takes over: it loops the sound in the app, vibrates, and swaps the chain for one silent notification that still has Stop / Snooze.

**Location.** Geofences are registered only for enabled location alarms, which keeps battery use down. Android does **not** deliver geofence events to a killed app. So while at least one location alarm is on, Hams_Alarm runs a low-power location foreground service, with a "Watching for your arrival" notification. That service keeps the process alive, and it doubles as a fallback detector with hysteresis. When no location alarms are on, the service stops.

**Time + Location** (`decideBoth` in `lib/time.ts`):

- Arrive early → an exact ring is scheduled for the set time, and cancelled if you leave.
- Time comes first → wait, then ring as soon as you arrive.
- The window ends without you arriving → that occurrence expires. A one-shot alarm switches off; a repeating one moves to its next day.

## Known limitations

These are worth reading before Monday.

- **Full-screen alarms come from a small patch** to expo-notifications (`patches/expo-notifications+58.1.9.patch`, applied by `patch-package` on install). It adds a full-screen intent to ringing notifications, so the screen wakes and the ring screen shows over the lock screen. `package.json` sets `expo.autolinking.android.buildFromSource: ["expo-notifications"]` so this patched source is compiled instead of the prebuilt AAR. **When you upgrade expo-notifications, re-create the patch.**
- **The sound repeats; it doesn't loop gaplessly** while the app is closed. Each follow-up notification replays the 28 s tone. Expect a short gap every 30 s for up to 5 minutes, then it stops.
- **Keep-alive notification.** While a location alarm is on, Android shows the "Watching for your arrival" notification. That's the cost of reliable arrival detection.
- **After a reboot**, Android 12+ won't let an app start a location foreground service from the background. The periodic task re-registers geofences. If it can't restart the keep-alive service, it posts a *"Location alarms paused – tap to resume"* notification. Time alarms are restored automatically by the OS.
- **Aggressive OEM battery savers** (some Xiaomi, Samsung, OnePlus, Huawei builds) can still kill background work. The permissions screen links to battery settings. Set Hams_Alarm to *Unrestricted*.
- **Geofence latency.** Android geofencing usually reports within about 1–2 minutes of entering, and can be slower in Doze. Pick a radius that gives you that much warning.
- **Place search** uses the device geocoder (Google Play services). Results are coordinates reverse-geocoded into labels. It's not a full place-autocomplete service.
- **Android only for now.** iOS was not a target and hasn't been tested.

## Regenerating assets

```bash
npm run sound                     # assets/sounds/alarm.wav (then rebuild — it's a native resource)
# App icon, splash and in-app art come from the Gemini originals in design/raw/ (see Design above).
```

If you change the alarm sound or the channel settings, bump `ALARM_CHANNEL` in `lib/notifications.ts`. Android locks a channel's settings once it has been created.
